## Why This Problem Matters

### The Real-World Pain

```
Small shopkeeper's daily reality:
├── Customer calls: "Bhaiya, do kilo chawal, ek litre tel, paanch packet namak"
├── Shopkeeper tries to write it down while serving another customer
├── Mishears "do kilo" as "do packet" → wrong quantity
├── Forgets one item → customer calls back angry
├── Calculates total manually → arithmetic error
├── Customer disputes the bill → lost trust
└── Repeat 50-100 times per day
```

### The Scale
- **12 million+** kirana stores in India
- Handle **~80%** of India's retail
- Most use **no digital ordering system**
- Orders happen in **Hinglish, regional languages, code-mixed speech**
- Shops are **noisy environments** — ideal for testing Prisma's noise handling

## Why It's Perfect for Gnani's Challenge

### 1. Deep Gnani Integration (Not Just Surface-Level)

Many participants will:
- Use Prisma for a simple transcription → ❌ Shallow integration
- Build a chatbot that talks → ❌ Generic use case

**VoiceOrder AI uses Gnani models in a business-critical pipeline:**

```
Prisma (STT) → Evon (Understanding) → Your Logic (Matching + Pricing) → Timbre (TTS)
      ↓                  ↓                        ↓                          ↓
  "Voice input"    "What items?"         "Real prices from DB"      "Read it back"
```

This shows judges you understand how to **integrate AI into a real workflow**, not just demo an API.

### 2. Demonstrates the Hardest Problem: Accuracy Over Fluency

Most projects just show "look, it transcribed!" — VoiceOrder AI goes further:
- **Ambiguity handling** — "do packet atta" → which size packet?
- **Validation** — AI can't guess prices; the database decides
- **Confirmation** — never auto-submit an order
- **Error recovery** — wrong item? Edit the transcript and re-extract

This is what makes a **real application** vs a **demo hack**.

### 3. Universally Relatable Story

For LinkedIn engagement (a major selection factor):
- Every Indian knows what a kirana store is
- Everyone has placed a verbal grocery order
- The pain of a wrong order is instantly understood
- "AI for local shops" is a viral-worthy narrative

## Risk Awareness (Shows Maturity)

| Risk | How VoiceOrder AI Handles It |
|------|------------------------------|
| Wrong quantity from STT | Editable transcript — user corrects before extraction |
| Wrong product match | Clarification required — never auto-select ambiguous matches |
| Wrong price | Database is source of truth — AI never decides prices |
| Double order submission | Idempotency key prevents duplicates |
| Timbre unavailable (beta) | Text summary fallback — confirmation still works |
| Unsupported language | Clear error message + typed input fallback |
